# Module M — Phase 1 Spike Results

Status: **complete, awaiting review**. This is a minimal spike, not the Module M
implementation. No migrations, CI/CD, staging, or full deployment system exist yet.

## Goal

Prove that the approved path works end to end before building Module M:

```
Cloudflare Python Workers -> FastAPI -> sync SQLModel/SQLAlchemy -> psycopg
    -> Cloudflare Hyperdrive -> Postgres
```

## Environment

| Item | Value |

| wrangler | 4.148.0 (global + local devDependency) |
| uv | 0.12.23 |
| Local dev interpreter | CPython 3.13.15 (uv venv) |
| Local DB for the DB path | PostgreSQL 16.15 (Homebrew), stand-in for Neon |

Note: the Worker runs CPython **3.14**, while the local uv venv uses 3.13.
Align `requires-python`/`.python-version` to 3.14 in Phase 2.

| 1 | FastAPI runs on Python Workers | PASS | `GET /health` -> 200 `{"status":"ok"}` in `pywrangler dev` |
| 2 | Sync SQLModel/SQLAlchemy works in the real runtime | PASS | `GET /sqlmodel-selftest` -> `{"sqlmodel":"ok","rows":1}` (in-memory SQLite, no network) |

Real Neon and a real (deployed) Hyperdrive config were **not** available in this

and local Postgres behind Hyperdrive's local mode.

## Key finding: the documented `asyncio.Lock` advice fails under concurrency

Cloudflare's Hyperdrive/Python-Workers doc suggests serializing synchronous DB
operations with an `asyncio.Lock`. Measured behavior (`GET /ready`, real DB ping):

| Concurrency | Lock ON (success) | Lock OFF (success) |
| --- | --- | --- |
| 1 | 30/30, median 7.7 ms | 10/10, median 7.0 ms |
| 3 | **1/30** | — |
| 10 | **1/50, then 0/30** | 50/50, median 33.6 ms |
| 20 | — | 100/100, median 69.0 ms |
| 25 | — | 200/200, median 64.9 ms (roundtrip 100/100, median 166 ms) |

With the lock ON, waiters starve while the holder runs a synchronous DB call, and
the Workers runtime cancels the queued requests:

> `The Workers runtime canceled this request because it detected that your Worker's code had hung`

Baseline `GET /health` (no DB): 50/50 at concurrency 10, median 12.3 ms, ~440 req/s.

**Conclusion:** do **not** use a global `asyncio.Lock`. Use a per-request engine
(`NullPool`) + per-request `Session`, so no mutable state is shared between
requests. This measured cleanly to concurrency 25.

## Bundle / limits

- `wrangler deploy --dry-run`: **Total Upload 34243 KiB (~33.4 MiB)** uncompressed,
  gzip 7660 KiB, **833 modules** — ~52% of the 64 MiB Worker size limit.
- Startup-time limit (1 s) and memory/CPU limits were not measurable locally.

## Not verified here (needs Cloudflare account + Neon)

## Deviations recorded

- Async SQLAlchemy/SQLModel is unsupported in Python Workers (no greenlet), as
  documented — the spike confirms the sync path is the correct choice.
